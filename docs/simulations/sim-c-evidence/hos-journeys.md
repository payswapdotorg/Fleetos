1. **J3 invite refusal (known defect, reproduced on all three firms):** a validly signed-in owner (GET /api/session 200, activeRole fleet.admin) clicks topbar "Invite member…" → alert `unknown_session` / "The session could not be found. Sign in again to continue." with only a "Dismiss the refusal" button. No dialog opens, no network request is emitted (request log byte-identical before/after the click). The member persona form (Ravi Patel / Omar Haddad / Leo Garnier) is unreachable because the dialog never opens → no join code can be issued in any real workspace → member-side redemption untestable → BLOCKED for LG/MD/SM. Matches the LEG/TRN/DEF/FEM reruns' identical finding.
2. **J2 deterministic fixture code + inert gated destructive (known defect, reproduced on all three firms):** code record "BOOT-W101-0001 / enr_w101_000001 / Created 2026-10-01T00:00:00Z — expires 2026-10-02T00:00:00.000Z" — identical visible code across all three tenants, fixture clock (not wall clock), zero /api/enrollment API calls (only Document GET /device/enrollment in the log). Display-once law itself HOLDS ("Shown once — copy it now…" → "The code was shown once and is now hidden…", no re-show affordance). "Disable this code…" (and the section-5 "Disable the enrollment code (requires authorization)") is INERT: no confirmation dialog, no toast, state stays "Active — active", no network request — the W13 "real confirmation flow" expectation is not met on this surface. Static disclaimer beside the button: "Disabling an enrollment code is an authorized operator action. The console routes it through the existing approval model — this surface never revokes by itself."
3. **NEW (beyond the known defects) — the J2 request counter is per-page-load client state:** each firm showed "Request | enr_w101_000001" after a FRESH navigation to /device/enrollment on this pass (LG, MD, SM all 000001) — the counter resets with the page rather than persisting per tenant or per browser, reinforcing that no server-side request sequence exists behind it.
4. **NEW minor — no visible re-create affordance after hiding the code:** once the one-time code is hidden, re-selecting platform (Windows/x64) and scope (Corporate-owned) does NOT re-offer "Create enrollment code" on the same surface; the copy "create a new request if you lost it" has no corresponding visible control until a fresh page load resets the surface.
5. **NEW micro-copy artifact:** the SM invite-surface copy concatenates the firm name with a trailing period: "Issue a one-time join code for Veranda Venue Co.. Expires 24 hours after the code is issued." (double period). Cosmetic only.
6. **Prior-artifact orphan tenants (operational note, not a product defect):** the gate picker lists SIX workspaces (two of each HOS firm name) because the earlier dead evaluator founded same-named tenants with the prescribed emails but an unknown password (POST /api/session 401 on `simc-rerun-2026`); the server permits the same member email to found multiple workspaces (POST /api/workspace 201), which is how the valid tenants above were re-provisioned. Picker ordering also re-shuffles after sign-out/join attempts (most-recently-used moves to the end) — cosmetic.
7. **Positive sub-check (negative join path, per firm):** "joinw-bogus-999" always yields the explicit `unknown_code` error "That join code does not match any workspace you can join from here. Check the code for typos, then ask the inviting workspace's administrator for a fresh invitation." — never a silent empty alert; validation is client-side (no network request).
